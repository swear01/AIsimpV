Hypotheses only. Nothing was compiled, simulated, or model-checked, and no equivalence was checked between this file and the upstream picorv32.v. Main changes: (1) The picorv32 module is hand-specialized to the wrapper's parameter set (COMPRESSED_ISA=1, ENABLE_FAST_MUL=1, ENABLE_DIV=1, BARREL_SHIFTER=1, everything else default). Logic that those parameters make unreachable was deleted: the IRQ machinery (irq_state, masks, timer, getq/setq/retirq/maskirq/waitirq/timer decode; eoi is tied to 0), trace, TWO_CYCLE_ALU/COMPARE and alu_wait, the iterative shift state and reg_sh, the ld_rs2 state (dualport regfile), the non-dualport regfile path, the PICORV32_REGS hook, the STACKADDR init, the !CATCH_MISALIGN path, TESTBUG/BLACKBOX ifdefs, DEBUG/ASCII/imm debug nets, and the FORMAL block (the SBY script uses read -sv, so FORMAL is not defined and those asserts were already inactive). The module parameter list is kept but ignored. (2) The unused picorv32_pcpi_mul body is replaced with tie-offs. This module is not instantiated by the specialized core. picorv32_regs, fast_mul, div, axi, adapter and wb are kept as is. Kept in full because ADD reaches the RVFI observation through them: the compressed-instruction expansion (C.ADD retires as an ADD encoding), the memory state machine with look-ahead, prefetch and half-word handling with arbitrary mem_ready/mem_rdata, the decoder, register file read/write, the rvfi_* pipeline, and the fast_mul/div PCPI paths, including their ALTOPS variants and timing, which affect earlier instructions. Not removed: any legal instruction class, memory traffic, or trap path. Information lost: behavior of picorv32 under any other parameters, IRQ/trace/other shift configurations, and use of the iterative multiplier. Expected relation to upstream: under the wrapper parameters the specialized RTL should be behaviorally identical, so the same BMC result is expected. The gain is a smaller elaborated netlist and fewer dead branches for Z3 to handle. That equivalence is untested and could fail from a transcription error. If it does, only a partial claim applies.
