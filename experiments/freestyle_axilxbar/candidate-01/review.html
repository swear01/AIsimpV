axilxbar：自由改寫審查

前端：原版與候選連接 property 後的 frontend 均 PASS；無 formal proof　DeepSeek Flash，單輪生成；來源 wb2axip 2e8d3bc；未做形式證明

此頁展示程式碼與解讀；前端通過及人工未見問題都不代表抽象正確。

第一份獨立生成候選把 4×8 crossbar 縮成 master 0／slave 0 的單一路徑讀取模型；property 本文保持原樣，環境說明另外限制其他流量。這是明確的局部問題，不足以推回原 crossbar 的驗證結果。

概念改動

1. 所有 master 0 讀取被接到 slave 0

原版以 addrdecode 和 grant/index 選擇 slave，也有無效地址的 error response；候選把地址直接送到 slave 0，其他 slave 的 ARVALID 固定為 0，且將 SLAVE_ADDR/MASK 預設值改成 0。

Property：hold property 不檢查來源或地址，因此仍可能成立；這個通過不能覆蓋原設計不同 slave 與 error path 的行為。

疑點：原版指向 slave 1 的讀取，在候選中被送往 slave 0；是否能把這份候選當成原題的局部替代，需要明確限定後續能推論的範圍。

人工狀態：程式碼支持此解讀

核對過 addrdecode 實例、原讀取回傳的 srindex/rgrant 選擇、候選固定接線；具體地址值尚未計算。

2. 回覆暫存器保留 stall 資料，但握手時機可疑

候選以 rvalid_q、rdata_q、rresp_q 直接記錄 slave 0 訊號，輸出 stall 時保持。原版則有路由、暫存與來源 ready 控制。

Property：候選的 hold branch 直接對應起始 assertion 的保持要求；但這只顯示候選寫了該保持條件，沒有證明它承接原設計的回覆行為。

疑點：候選在輸出 valid=0、ready=0 時可捕捉 M_AXI_RVALID=1，但同時令 M_AXI_RREADY=0，亦即沒有完成 slave 握手。之後 ready=1 時又可捕捉同一筆仍有效的資料，造成重複回覆的可能。

人工狀態：有具體疑點

逐拍推導自候選 80–96 行；尚未用模擬或 formal 工具重播，不宣稱已找到原設計與候選的正式反例。

3. 寫入與其他端口被關閉

候選將全部寫入回覆、寫入有效訊號，以及其他 master/slave 的部分讀取端口固定為 0；原版保有相應回覆與路由邏輯。

Property：這些端口不直接出現在起始 property，但其流量與仲裁可能影響讀取路徑；是否可安全省略仍未判定。

疑點：模型的環境說明稱這些流量 idle，原始 task 則讓全部 design inputs 自由；不能直接把候選的環境限制套回原題。

人工狀態：程式碼支持刪除；關係不明

核對過原 B 回覆與候選 tie-off。沒有檢查所有寫入/讀取仲裁交互作用。

4. Property 本文不變，環境說明另行縮窄

候選 property 的 assert 與 reset guard 同原版；另在文字中要求只考慮 master 0／slave 0 讀取，且其他流量 idle。

Property：沒有看到自主改寫 property 表示；事後已將 property 接到原版與候選並通過 frontend，但未執行 property proof。

疑點：將更窄的環境當成同一道題會誇大候選價值。

人工狀態：程式碼支持此解讀

比較了兩份 assertion、task.json 與候選環境文字；原 property 只有 17 行，獨立分析的第 18 行引用已修正於本卡。補做結果見 bound_frontend.txt。

生成者說明

This is a reduced observation model, not an equivalent crossbar replacement. The original multi-master, multi-slave AXI-Lite crossbar is replaced by a minimal top with the same interface. Only master 0 and slave 0 have an active read path. The read return channel is a single registered hold stage: it captures M_AXI_RVALID[0], M_AXI_RDATA[0], and M_AXI_RRESP[0] when not stalled, and explicitly holds rvalid_q, rdata_q, and rresp_q when S_AXI_RVALID[0] is high and S_AXI_RREADY[0] is low. All write channels and all other read masters/slaves are tied inactive. The property module is the same read-hold safety property for master 0. Expected relationship: proving this property on the simplified model discharges the core stalled-read-response hold obligation for the selected channel. Conjecture: this does not prove the original crossbar arbitration, decoding, error response, multi-master, or multi-slave behavior. The simplification is relevant because the original property is a local read-return stability property, and the reduced RTL isolates exactly that obligation.

環境變動

Original environment: no additional assumptions; all design inputs are free; reset guards both observed edges. New candidate environment changes: restrict attention to master 0 and slave 0 read traffic; all write inputs are treated as idle/inactive; other masters and other slaves are idle/inactive. The simplified RTL does not require an assumption that M_AXI_RVALID[0], M_AXI_RDATA[0], or M_AXI_RRESP[0] must remain stable while stalled, because the registered hold stage enforces the property internally. The reset guard on the observed edges is unchanged. SLAVE_ADDR, SLAVE_MASK, OPT_LINGER, and LGMAXBURST are kept only for interface compatibility and are not used by the simplified behavior. The property binding is unchanged: clk=S_AXI_ACLK, resetn=S_AXI_ARESETN, rvalid=S_AXI_RVALID[0], rready=S_AXI_RREADY[0], rdata=S_AXI_RDATA[0+:32], rresp=S_AXI_RRESP[0+:2].

7// Purpose: Create a full crossbar between NM AXI-lite sources (masters),

9// provided it isn't already busy.
10//
11// Performance: This core has been designed with the goal of being able to push
12// one transaction through the interconnect, from any master to
13// any slave, per clock cycle. This may perhaps be its most unique
14// feature. While throughput is good, latency is something else.
15//
16// The arbiter requires a clock to switch, then another clock to send data
17// downstream. This creates a minimum two clock latency up front. The
18// return path suffers another clock of latency as well, placing the
19// minimum latency at four clocks. The minimum write latency is at
20// least one clock longer, since the write data must wait for the write
21// address before proceeeding.
22//
23// Usage: To use, you must first set NM and NS to the number of masters
24// and the number of slaves you wish to connect to. You then need to
25// adjust the addresses of the slaves, found SLAVE_ADDR array. Those
26// bits that are relevant in SLAVE_ADDR to then also be set in SLAVE_MASK.
27// Adjusting the data and address widths go without saying.
28//
29// Lower numbered masters are given priority in any "fight".
30//
31// Channel grants are given on the condition that 1) they are requested,
32// 2) no other channel has a grant, 3) all of the responses have been
33// received from the current channel, and 4) the internal counters are
34// not overflowing.
35//
36// The core limits the number of outstanding transactions on any channel to
37// 1<<LGMAXBURST-1.
38//
39// Channel grants are lost 1) after OPT_LINGER clocks of being idle, or
40// 2) when another master requests an idle (but still lingering) channel
41// assignment, or 3) once all the responses have been returned to the
42// current channel, and the current master is requesting another channel.
43//
44// A special slave is allocated for the case of no valid address.
45//
46// Since the write channel has no address information, the write data
47// channel always be delayed by at least one clock from the write address
48// channel.
49//
50// If OPT_LOWPOWER is set, then unused values will be set to zero.
51// This can also be used to help identify relevant values within any
52// trace.
