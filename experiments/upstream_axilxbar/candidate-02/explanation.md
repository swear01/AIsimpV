This candidate replaces the original dynamic read-grant state machine with a purely combinational, fixed-priority per-slave arbiter. The new internal representation uses rrequest from addrdecode, and derives rgrant, srgrant, srindex, mrgrant, and mrindex combinationally. By construction, each master's rgrant is one-hot, each real slave has at most one master, and the reciprocal slave-side index matches the granted master. The rewritten FORMAL property checks exactly the original read-grant consistency assertions (one selected route per master, matching source index, and reciprocal slave grant/index) on these new signals. The proof is therefore much simpler: it no longer needs to reason about lingering grants, outstanding transaction counters, cross-cycle arbitration, or error-slave sharing. This is a partial candidate. It does not represent the write channel, read data return path, skid buffers, full AXI handshaking, multiple outstanding transactions, or the original round-robin/priority arbitration history. It also changes the arbitration policy to fixed priority (lowest master index) per slave. It assumes read requests are one-hot from addrdecode, which is true for the original addrdecode. The property is checked combinationally; no clocked state is involved in the read grants. This does not prove the full crossbar, only the read-grant consistency invariant under the simplified combinational grant model.
