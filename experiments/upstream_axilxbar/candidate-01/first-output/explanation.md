This candidate simplifies the read-grant consistency assertions in CHECK_MASTER_GRANTS. The original code loops over every possible iM and asserts, for each set bit, that rgrant is one-hot, srgrant is set, srindex equals that bit, and the reciprocal slave-side mrgrant/mrindex match. The candidate replaces that loop with a direct one-hot/equality check: if srgrant is set, then srindex must be a valid index and rgrant must equal `1 << srindex`. If the selected index is a real slave, it checks `mrgrant[srindex]` and `mrindex[srindex] == N`. It also keeps the original exclusivity check for the error route. This is logically equivalent to the original read-grant obligations under the assumption that `srindex` is meaningful when granted, and it removes the per-bit loop. It addresses the original read-grant assertions: one-hot route selection, source-index match, reciprocal slave grant/index, and error-route exclusivity. It does not address write-grant consistency, outstanding counters, data-path integrity, address decode correctness, AXI handshake behavior, or full crossbar throughput. This is a partial candidate: the full RTL problem cannot be simplified here without losing many crossbar behaviors, so the simplification is limited to the read-grant consistency block.
