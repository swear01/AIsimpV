# PicoRV32 majority-behavior rewrite

This experiment explores **one shared simplified PicoRV32 model at a time** for most tasks in the pinned upstream riscv-formal configuration. The input is the complete original core, its wrapper, and the [86 generated assertion-task names and intent groups](assertion_intents.md). The initial candidates were 01 (omit M) and 02 (abstract register reads). A [mapped-cell follow-up](mapped_size.md) adds candidate 03 (single-port registers), 04 (eight-step iterative M), and 05 (omit M plus single-port registers). Candidates 03–05 are engineering controls constructed directly from existing upstream implementation options, not independent freestyle generations. The generated cover task and three separately maintained `.sby` files are recorded but excluded from this denominator. The prior [ADD-only pilot](../picorv32/README.md) is a separate experiment.

The target of roughly 80% means at least 69 of those 86 task intentions would need credible behavioral support in the *same* candidate. The later JasperGold run measures **72/86 bounded assertion-task passes** for candidate 05, above that numerical threshold, but **not a measured behavior-inclusion rate**. Task names are correlated; the report also separates RV32I, M, compressed instructions, register/PC/order, and CSR behavior. An opcode decoder, an assertion that passes, or a model-written explanation alone is insufficient evidence of abstraction soundness. The candidate must still represent meaningful nonzero data and instruction sequences for a task to be considered retained by inspection.

The initial two-candidate phase did not run Formal or simulation; the mapped-cell follow-up added only small VCS simulations of selected behavior. The subsequent 86-task assertion check uses **JasperGold directly** with the pinned upstream RTL/SVA harness; see [JasperGold results and reproduction](jasper_results.md). For future RTL assertion runs on this machine, prefer JasperGold when available. A size-only Yosys synthesis comparison remains in [structural_size.md](structural_size.md), and mapped standard-cell counts from Design Compiler are in [mapped_size.md](mapped_size.md). Neither a bounded assertion pass nor a size reduction proves equivalence, abstraction soundness, or the 80% behavior target. Candidate 02 uses the `$anyseq` construct whose time-step semantics are documented by [YosysHQ](https://yosyshq.readthedocs.io/projects/yosys/en/v0.56/using_yosys/verilog.html); Design Compiler cannot map it directly.

The wrapper configuration is fixed at `COMPRESSED_ISA=1`, `ENABLE_FAST_MUL=1`, `ENABLE_DIV=1`, and `BARREL_SHIFTER=1`, with the original memory inputs and reset connection. The pinned source revisions are in [task.json](task.json). The `upstream` link points to the unchanged source snapshot in the adjacent PicoRV32 case.
